## 2. New findings introduced since 04-13

### N1 (CRITICAL) — Prisma migrations mounted as Postgres initdb

**File:** `docker-compose.production.yml`

```yaml
volumes:
  - ./backend/prisma/migrations:/docker-entrypoint-initdb.d:ro
```

Postgres' initdb runs only `*.sql`, `*.sh`, `*.sql.gz` at the top level of that directory. Prisma's migration tree is `migrations/<timestamp>_name/migration.sql` — nested one directory deep. On a fresh prod volume the DB starts **empty**, then `prisma migrate deploy` runs from the app container. The mount is at best inert, at worst lets an attacker land a `migrations/zzz_pwn/migration.sql` that overrides expectations during a future refactor.

**Fix:** Drop the mount. Let `prisma migrate deploy` own migrations.

### N2 (HIGH) — `datacendia-marketing` has no CI, no Dependabot, no SECURITY.md

The public-facing marketing surface has **zero automated security hygiene**. No CodeQL, no secret scanning, no dep updates. Any XSS, outdated dep, or leaked key in that repo is caught only by manual review.

**Fix:** Copy the `security.yml` from core (TruffleHog + CodeQL), add `dependabot.yml`, and add a minimal `SECURITY.md` pointing to `security@datacendia.com`.

### N3 (HIGH) — TruffleHog `@main` across three repos

Already captured as H10 in 04-13, but now present in three workflows — **supply-chain blast radius has widened.** Pin to an immutable SHA (e.g. `trufflesecurity/trufflehog@<commit>`), not `@main`.

### N4 (MEDIUM) — Open-PR backlog

- `datacendia-components`: **>20 open Dependabot PRs** (Express, Helmet, jose, prisma, react, react-router-dom, vitest, uuid, neo4j-driver, aws-sdk, types/node, jsdom, testing-library, plus 5 GHA bumps + 2 Docker base bumps).
- `datacendia-core` + `datacendia-components`: **>10 stale `copilot/…` draft branches each** (some >30 days old).
- `decision-governance-infrastructure`: one long-lived PR #1 still open.

**Risk:** Branch sprawl hides real work, increases merge-conflict cost, and invites a stale branch being merged without re-review. Batch the Dependabot PRs by category, close the abandoned copilot drafts.

### N5 (MEDIUM) — `core` CI vs `components` CI inconsistency

`datacendia-components` CI enforces `lint --max-warnings -1` and removes `continue-on-error`; `datacendia-core` does not. The stricter repo is the *smaller* one. Promote the components CI template to core.

### N6 (LOW) — Duplicate `main` and `master` branches on core

`datacendia-core` has both `main` (`d2989a0…`) and `master` (`384c8f3…`), diverged. Developers cutting PRs against the wrong default risk losing work. Pick one, redirect the other.
